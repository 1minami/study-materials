# 運用管理作業

> S2.5 基本的な運用管理作業（重要度**7**）。7問前後。VACUUM と VACUUM FULL の違い、autovacuum、ロールと GRANT / REVOKE、テーブルスペース、システムカタログが定番。

## 1. VACUUM ★★★

### なぜ必要か

- PostgreSQL は **MVCC**: UPDATE は「古い行を無効にして新しい行を追加」、DELETE は「行を無効にする」だけで、**古い行（不要タプル / dead tuple）が物理的に残る**
- 放っておくとテーブルが膨れ（肥大化）、検索が遅くなる → **VACUUM** で不要な行の領域を回収する
- VACUUM の役割
  1. 不要タプルの領域を**再利用できるようにする**
  2. **可視性マップ**を更新する（Index Only Scan を速くする）
  3. **トランザクション ID の周回（wraparound）を防ぐ**（古い行を凍結 = FREEZE する）
  4. ANALYZE を付ければ統計情報も更新

### VACUUM と VACUUM FULL

| | **VACUUM**（通常） | **VACUUM FULL** |
|---|---|---|
| 動作 | 不要領域を**再利用可能にする** | テーブルを**新しいファイルに書き直して詰める** |
| ディスク容量 | **OS には基本返さない**（末尾の空きページだけ返す） | **OS に返す**（ファイルが小さくなる） |
| ロック | SHARE UPDATE EXCLUSIVE（**読み書きと並行して実行できる**） | **ACCESS EXCLUSIVE**（**SELECT も含めて全操作が止まる**） |
| 必要な空き容量 | ほぼ不要 | テーブルの**コピーを作る分の空き容量が必要** |
| 時間 | 短い | 長い |
| 実行頻度 | 日常的に（autovacuum が自動で行う） | 極端に肥大化したときだけ |

- ⚠ **VACUUM FULL はテーブルを排他ロックする**。運用中に実行すると業務が止まる
- ⚠ **autovacuum は VACUUM FULL を実行しない**

### 書き方

```sql
VACUUM;                         -- 現在のデータベースの全テーブル
VACUUM emp;                     -- テーブルを指定
VACUUM FULL emp;
VACUUM ANALYZE emp;             -- VACUUM の後に ANALYZE
VACUUM VERBOSE emp;             -- 処理の詳細を表示
VACUUM FREEZE emp;              -- 行を積極的に凍結
VACUUM (FULL, VERBOSE, ANALYZE) emp;   -- 括弧でまとめて指定
```

- ⚠ **VACUUM はトランザクションブロック内で実行できない**（→ 04章）
- テーブルの所有者・DB の所有者・スーパーユーザーが実行できる（権限のないテーブルは警告を出して飛ばす）
- OS のコマンドからは **vacuumdb**（→ 05章）

### トランザクション ID の周回

- トランザクション ID（XID）は **32ビット**（約42億）で、使い切ると一周する。行の新旧を比べられるのは前後約 **20億**まで
- 古い行を **凍結（FREEZE）** して「どのトランザクションから見ても過去」の印を付けないと、**古いデータが見えなくなる**（データ消失に見える）
- そのため、autovacuum を off にしていても、周回が近づくと**周回防止のための autovacuum が強制的に実行**される（autovacuum_freeze_max_age、デフォルト **2億**トランザクション）

## 2. ANALYZE ★★★

```sql
ANALYZE;              -- 現在のデータベースの全テーブル
ANALYZE emp;
ANALYZE emp (name);   -- 列を指定
ANALYZE VERBOSE emp;
```

- テーブルの**統計情報**（行数、列の値の分布、NULL の割合など）を集め、システムカタログ **pg_statistic** に保存する（見やすい形のビューは **pg_stats**）
- 統計情報は**プランナ（実行計画を立てる部分）**が使う。古いと**遅い実行計画**が選ばれる
- テーブル全体ではなく**サンプリング**した行を読む（大きいテーブルでも速い）
- ロックは SHARE UPDATE EXCLUSIVE（読み書きと並行できる）
- ⚠ ANALYZE は**トランザクションブロック内でも実行できる**（VACUUM はできない）
- 大量のデータを入れた後（COPY、大きな INSERT）は ANALYZE を実行すると良い

## 3. autovacuum（自動バキューム） ★★★

- **autovacuum ランチャー**が定期的に起動し、**autovacuum ワーカー**が必要なテーブルに **VACUUM と ANALYZE を自動実行**する
- **デフォルトで有効**（autovacuum = **on**）

| パラメータ | デフォルト | 意味 |
|---|---|---|
| **autovacuum** | **on** | autovacuum を使う（sighup） |
| **track_counts** | **on** | テーブルの更新件数などの統計を集める。⚠ **off にすると autovacuum が動かない** |
| **autovacuum_naptime** | **1min** | 各データベースをチェックする間隔 |
| **autovacuum_max_workers** | **3** | 同時に動くワーカーの最大数（postmaster） |
| autovacuum_vacuum_threshold | 50 | VACUUM するための最小の不要タプル数 |
| **autovacuum_vacuum_scale_factor** | **0.2** | テーブルの行数に対する割合（20%） |
| autovacuum_analyze_threshold | 50 | ANALYZE するための最小の変更行数 |
| autovacuum_analyze_scale_factor | 0.1 | テーブルの行数に対する割合（10%） |
| autovacuum_freeze_max_age | 2億 | 周回防止の VACUUM を強制する XID の年齢 |
| log_autovacuum_min_duration | -1（無効） | 指定時間以上かかった autovacuum をログに出す |

- VACUUM が実行される条件: **不要タプル数 > autovacuum_vacuum_threshold + autovacuum_vacuum_scale_factor × 行数**
  - 例: 1万行のテーブル → 50 + 0.2 × 10000 = **2,050行**を超えると VACUUM
- ANALYZE も同様（50 + 0.1 × 行数 を超える変更）
- テーブルごとに変えられる: `ALTER TABLE emp SET (autovacuum_vacuum_scale_factor = 0.05);`、`ALTER TABLE emp SET (autovacuum_enabled = false);`
- 実行状況は **pg_stat_user_tables** で確認: `n_live_tup`（有効な行数）、**`n_dead_tup`（不要タプル数）**、`last_vacuum` / **`last_autovacuum`**、`last_analyze` / `last_autoanalyze`

## 4. その他のメンテナンス ★★

| コマンド | 動作 | ロック |
|---|---|---|
| **REINDEX** | **インデックスを作り直す**（肥大化・破損したインデックスの修復） | 対象テーブルへの書き込みを止める |
| REINDEX ... CONCURRENTLY | 書き込みを止めずに作り直す（12〜） | |
| **CLUSTER** | テーブルを**インデックスの順に並べ直して**書き直す | **ACCESS EXCLUSIVE** |
| **CHECKPOINT** | すぐにチェックポイントを実行（スーパーユーザー） | |

```sql
REINDEX INDEX emp_name_idx;
REINDEX TABLE emp;          -- テーブルの全インデックス
REINDEX DATABASE sampledb;  -- データベース内の全インデックス（現在のDBのみ指定可）
REINDEX SYSTEM sampledb;    -- システムカタログのインデックス
CLUSTER emp USING emp_name_idx;
CLUSTER emp;                -- 前回と同じインデックスで
```

- ⚠ CLUSTER の並べ替えは**その時だけ**。その後の INSERT / UPDATE では順序は保たれない（自動では維持されない）
- ⚠ CLUSTER もテーブルを書き直すので、VACUUM FULL と同様に**不要領域も回収**される

## 5. ロール（ユーザー）の管理 ★★★

### ロールとは

- PostgreSQL では**ユーザーとグループを区別せず「ロール」**として扱う
- **ログインできるロール = ユーザー**、他のロールをメンバーにまとめるロール = グループ
- ⚠ ロールは**クラスタ全体**で共通（データベースごとではない）。pg_dump では出力されない（→ 07章）

### CREATE ROLE / CREATE USER

```sql
CREATE ROLE alice LOGIN PASSWORD 'secret';
CREATE USER bob PASSWORD 'secret' CREATEDB VALID UNTIL '2027-03-31';
CREATE ROLE staff;                    -- グループ用（ログイン不可）
```

- ⚠ **CREATE USER は LOGIN 付きの CREATE ROLE**。**CREATE ROLE のデフォルトは NOLOGIN**（ログインできない）

| 属性 | 意味 | デフォルト |
|---|---|---|
| **SUPERUSER** / NOSUPERUSER | **すべての権限チェックを飛ばす** | NOSUPERUSER |
| **CREATEDB** / NOCREATEDB | データベースを作れる | NOCREATEDB |
| **CREATEROLE** / NOCREATEROLE | ロールを作成・変更・削除できる | NOCREATEROLE |
| **LOGIN** / NOLOGIN | ログインできる | CREATE ROLE は NOLOGIN、CREATE USER は LOGIN |
| REPLICATION / NOREPLICATION | レプリケーション接続・pg_basebackup ができる | NOREPLICATION |
| **INHERIT** / NOINHERIT | メンバーになっているロールの権限を**自動で引き継ぐ** | INHERIT |
| BYPASSRLS | 行単位セキュリティを無視する | NOBYPASSRLS |
| **PASSWORD '...'** | パスワード | なし |
| **VALID UNTIL '日時'** | **パスワード**の有効期限 | 無期限 |
| CONNECTION LIMIT n | 同時接続数の上限 | -1（無制限） |

- ⚠ VALID UNTIL は**パスワードの期限**（ロール自体が消えるわけではない。peer 認証などでは影響しない）

### ALTER ROLE / DROP ROLE

```sql
ALTER ROLE alice CREATEDB;
ALTER ROLE alice PASSWORD 'newpass';
ALTER ROLE alice RENAME TO alice2;     -- MD5 パスワードは名前を含むので消える
ALTER ROLE alice SET work_mem = '16MB';  -- 接続時のパラメータ（→ 06章）
DROP ROLE alice;
DROP ROLE IF EXISTS alice;
```

- ⚠ **オブジェクトを所有している、または権限を与えられているロールは DROP ROLE できない**（エラー）。先に次を実行する
  - **`REASSIGN OWNED BY alice TO bob;`**: alice が所有するオブジェクトの**所有者を bob に変える**
  - **`DROP OWNED BY alice;`**: alice が所有するオブジェクトを**削除**し、alice に与えた権限も取り消す
  - ⚠ どちらも**今のデータベースの中だけ**が対象。他のデータベースでも実行する必要がある

### ロールのメンバーシップ（グループ）

```sql
GRANT staff TO alice;          -- alice を staff のメンバーにする
REVOKE staff FROM alice;
SET ROLE staff;                -- staff として振る舞う（RESET ROLE で戻る）
```

- INHERIT（デフォルト）なら、alice は**何もしなくても staff の権限を使える**。NOINHERIT なら SET ROLE が必要
- ⚠ **SUPERUSER・CREATEDB などの属性はメンバーシップで継承されない**（権限だけが継承される）。使うには SET ROLE が必要

### 定義済みロール

| ロール | 内容 |
|---|---|
| **pg_read_all_data** | すべてのテーブルを読める（14〜） |
| **pg_write_all_data** | すべてのテーブルに書ける（14〜） |
| pg_read_all_settings / pg_read_all_stats | 全設定 / 全統計情報を見られる |
| pg_monitor | 監視用（上の2つなどを含む） |
| pg_read_server_files / pg_write_server_files | サーバのファイルを COPY で読める / 書ける |
| pg_signal_backend | 他のセッションのキャンセル・終了ができる |

## 6. 権限（GRANT / REVOKE） ★★★

### 基本

- オブジェクトを作ったロールが**所有者**になり、**所有者はすべての権限**を持つ（ALTER・DROP できるのは所有者とスーパーユーザーだけ）
- 他のロールは、**GRANT で権限を与えられないと**使えない
- **スーパーユーザーは権限チェックを受けない**

```sql
GRANT SELECT, INSERT ON emp TO alice;
GRANT ALL PRIVILEGES ON emp TO alice;       -- PRIVILEGES は省略可
GRANT SELECT ON ALL TABLES IN SCHEMA app TO alice;  -- スキーマ内の既存の全テーブル
GRANT SELECT (id, name) ON emp TO bob;      -- 列単位
GRANT UPDATE (salary) ON emp TO bob;
GRANT SELECT ON emp TO PUBLIC;              -- 全ロール
GRANT SELECT ON emp TO alice WITH GRANT OPTION;  -- alice も他人に与えられる
REVOKE INSERT ON emp FROM alice;
REVOKE ALL ON emp FROM PUBLIC;
REVOKE GRANT OPTION FOR SELECT ON emp FROM alice;  -- 再付与の権利だけ取り消す
ALTER TABLE emp OWNER TO bob;               -- 所有者の変更
```

- **PUBLIC**: **すべてのロール**（今後作られるロールも含む）を表す特別な名前
- ⚠ **WITH GRANT OPTION** で受け取った権限を他人に与えていた場合、元の権限を REVOKE するには **CASCADE** が必要（付けないとエラー）
- ⚠ PUBLIC から REVOKE しても、**個別に GRANT された権限は残る**
- ⚠ `ON ALL TABLES IN SCHEMA` は**今あるテーブルだけ**。今後作るテーブルにも与えるには **`ALTER DEFAULT PRIVILEGES`**
- 確認: psql の **`\dp`** / **`\z`**（例: `alice=arw/postgres` = postgres が alice に a・r・w を与えた）

### 主な権限

| 対象 | 権限 |
|---|---|
| **テーブル** | **SELECT**（r）、**INSERT**（a）、**UPDATE**（w）、**DELETE**（d）、**TRUNCATE**（D）、**REFERENCES**（x。外部キーで参照する）、**TRIGGER**（t） |
| 列 | SELECT、INSERT、UPDATE、REFERENCES |
| シーケンス | **USAGE**（nextval・currval）、SELECT（currval）、UPDATE（nextval・setval） |
| **データベース** | **CONNECT**（接続）、**CREATE**（スキーマを作る）、**TEMPORARY**（一時テーブルを作る） |
| **スキーマ** | **USAGE**（中のオブジェクトにアクセス）、**CREATE**（中にオブジェクトを作る） |
| 関数・プロシージャ | **EXECUTE** |
| テーブルスペース | CREATE |

- ⚠ テーブルの SELECT 権限があっても、**そのスキーマの USAGE 権限がないとアクセスできない**
- ⚠ UPDATE・DELETE で WHERE を使うと、条件の列を読むため **SELECT 権限も必要**
- ⚠ 外部キーを作るには、参照先テーブルの **REFERENCES** 権限が必要

### PUBLIC にデフォルトで与えられている権限（14）

- データベース: **CONNECT**、**TEMPORARY**
- 関数: **EXECUTE**
- **public スキーマ: USAGE と CREATE**（⚠ 15 で CREATE は外された。試験は 14 基準）
- ⚠ **テーブル・ビュー・シーケンスには何も与えられていない**（所有者以外は GRANT が必要）
- 特定のデータベースへの接続を制限するには `REVOKE CONNECT ON DATABASE sampledb FROM PUBLIC;` してから、必要なロールに GRANT CONNECT する（pg_hba.conf でも制限できる）

## 7. データベースの作成・削除 ★★★

```sql
CREATE DATABASE sampledb;
CREATE DATABASE sampledb
  OWNER alice
  TEMPLATE template0
  ENCODING 'UTF8'
  LC_COLLATE 'C'
  LC_CTYPE 'C'
  TABLESPACE fastspace
  CONNECTION LIMIT 50;
ALTER DATABASE sampledb RENAME TO sample2;
ALTER DATABASE sampledb OWNER TO bob;
DROP DATABASE sampledb;
DROP DATABASE IF EXISTS sampledb;
DROP DATABASE sampledb WITH (FORCE);   -- 接続中のセッションを切断して削除（13〜）
```

- **CREATE DATABASE は既存のデータベースを複製**して作る。デフォルトの複製元は **template1**
  - template1 に入れたテーブルや拡張機能は、**以後作るデータベースにも入る**
  - **template0** は initdb 直後の素の状態。**template1 と違うエンコーディング・ロケールで作るときは template0 を指定**する（template1 のままだとエラー）
- 実行できるのは **CREATEDB 属性**を持つロールかスーパーユーザー
- ⚠ **複製元のデータベースに他のセッションが接続していると CREATE DATABASE は失敗**する
- ⚠ **DROP DATABASE は、そのデータベースに誰か接続していると失敗**する（自分が接続中のデータベースも削除できない）。13 以降は WITH (FORCE) で切断して削除できる
- ⚠ CREATE DATABASE / DROP DATABASE は**トランザクションブロック内で実行できない**
- DROP DATABASE できるのは**所有者**とスーパーユーザー

## 8. テーブルスペース ★★★

- **データファイルを置くディレクトリに名前を付けたもの**。容量が足りないとき、速いディスクに特定のテーブルを置きたいときに使う

```sql
CREATE TABLESPACE fastspace LOCATION '/ssd/pgdata';
CREATE TABLESPACE fastspace OWNER alice LOCATION '/ssd/pgdata';
CREATE TABLE logs (...) TABLESPACE fastspace;
CREATE INDEX ... ON logs (...) TABLESPACE fastspace;
ALTER TABLE logs SET TABLESPACE pg_default;   -- 移動（ACCESS EXCLUSIVE ロック）
SET default_tablespace = fastspace;           -- テーブルスペース省略時の作成先
DROP TABLESPACE fastspace;
```

- ⚠ LOCATION は**絶対パス**。ディレクトリは**あらかじめ存在し、空で、OS の postgres ユーザーが所有**していること（作ってはくれない）
- ⚠ CREATE TABLESPACE は**スーパーユーザー**だけが実行できる。トランザクションブロック内では実行できない
- ⚠ **中にオブジェクトが残っているテーブルスペースは DROP できない**（全データベースで空にする必要がある）
- データディレクトリの **pg_tblspc/** に、テーブルスペースの OID の名前で**シンボリックリンク**ができる
- 初めからある2つ

| テーブルスペース | 内容 |
|---|---|
| **pg_default** | データベースの**デフォルト**（template1・template0 の格納先）。実体は **base/** |
| **pg_global** | **クラスタ共通のシステムカタログ**用。実体は **global/** |

- テーブルスペースは**クラスタ全体**で共通（pg_dump では出力されない → pg_dumpall）
- 確認: psql の **`\db`**、システムカタログ **pg_tablespace**

## 9. システムカタログと情報スキーマ ★★★

### システムカタログ

- PostgreSQL が自分の管理情報（テーブル・列・ロールなどの定義）を入れているテーブル。**pg_catalog スキーマ**にあり、名前は **pg_** で始まる
- search_path に書かなくても、**pg_catalog は常に最初に検索**される

| カタログ / ビュー | 内容 |
|---|---|
| **pg_database** | **データベース**の一覧（クラスタ共通） |
| **pg_class** | **テーブル・インデックス・シーケンス・ビューなど**（リレーション）。**relkind** 列で種類を区別 |
| **pg_attribute** | テーブルの**列** |
| **pg_namespace** | **スキーマ** |
| pg_index | インデックスの詳細 |
| pg_proc | 関数・プロシージャ |
| pg_type | データ型 |
| **pg_authid** | **ロール**（パスワードを含む。スーパーユーザーのみ読める） |
| **pg_roles** | ロール（pg_authid のパスワードを伏せたビュー。誰でも読める） |
| pg_user | LOGIN できるロールのビュー |
| pg_tablespace | テーブルスペース |
| **pg_tables** / pg_indexes / pg_views | テーブル / インデックス / ビューを見やすくしたビュー |
| **pg_settings** | **パラメータの現在値**（→ 06章） |
| pg_statistic / **pg_stats** | 統計情報（→ ANALYZE） |
| **pg_locks** | 現在の**ロック**（→ 04章） |

- **pg_class の relkind**: **`r`** = テーブル、**`i`** = インデックス、**`S`** = シーケンス、**`v`** = ビュー、`m` = マテリアライズドビュー、`t` = TOAST テーブル、`f` = 外部テーブル、`p` = パーティションテーブル、`c` = 複合型
- 多くのオブジェクトは **OID**（オブジェクト識別子）で識別される。`SELECT oid, datname FROM pg_database;`

### 統計情報ビュー

| ビュー | 内容 |
|---|---|
| **pg_stat_activity** | **今の接続（セッション）**と実行中の SQL（pid、usename、datname、**state**、**query**、client_addr） |
| **pg_stat_user_tables** | テーブルごとのアクセス件数・不要タプル数・VACUUM / ANALYZE の実行時刻 |
| pg_stat_user_indexes | インデックスごとの使用回数 |
| pg_stat_database | データベースごとのコミット数・ロールバック数・キャッシュヒット数 |
| pg_stat_archiver | WAL アーカイブの状況（→ 07章） |
| pg_stat_replication | レプリケーションの状況 |

- 実行中の処理を止める関数
  - **`pg_cancel_backend(pid)`**: その**問い合わせを中止**する（**セッションは残る**）
  - **`pg_terminate_backend(pid)`**: その**セッションを切断**する
- 統計をリセット: `SELECT pg_stat_reset();`（現在のデータベース）

### 情報スキーマ（information_schema）

- **SQL 標準**で定められたビューの集まり。**他の DBMS でも同じ問い合わせ**が使える（移植性が高い）
- 例: `information_schema.tables`、`information_schema.columns`、`information_schema.views`、`information_schema.table_privileges`
- ⚠ PostgreSQL 独自の情報（インデックスなど）は含まない。それらは**システムカタログ**で見る

```sql
SELECT table_name FROM information_schema.tables WHERE table_schema = 'public';
SELECT column_name, data_type FROM information_schema.columns WHERE table_name = 'emp';
```

### サイズを調べる関数

| 関数 | 返す値 |
|---|---|
| **pg_database_size('DB名')** | データベースのサイズ（バイト） |
| **pg_relation_size('テーブル')** | テーブル本体のサイズ（インデックス・TOAST を含まない） |
| **pg_total_relation_size('テーブル')** | テーブル + **インデックス + TOAST** の合計 |
| pg_table_size('テーブル') | テーブル + TOAST（インデックスを含まない） |
| pg_indexes_size('テーブル') | そのテーブルのインデックスの合計 |
| **pg_size_pretty(バイト数)** | **'8192 bytes'・'15 MB'** のような**読みやすい表記**に変換 |

- 例: `SELECT pg_size_pretty(pg_database_size('sampledb'));`
