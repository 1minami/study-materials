# 関数・トランザクション

> S3.2 組み込み関数（重要度2）＋ S3.3 トランザクションの概念（重要度1）。合わせて3問前後だが、トランザクションの知識は運用管理（ロック・VACUUM）の問題でも前提になる。

## 1. 演算子と型変換 ★★

### 算術演算子

| 演算子 | 例 | 結果 |
|---|---|---|
| `+` `-` `*` | `2 * 3` | 6 |
| **`/`** | `7 / 2` | **3**（整数同士は**小数点以下切り捨て**） |
| | `7.0 / 2` | 3.5000000000000000 |
| **`%`** | `7 % 2` | 1（剰余） |
| **`^`** | `2 ^ 3` | 8（べき乗） |
| `@` | `@ -5` | 5（絶対値） |

- ⚠ **整数 ÷ 整数は整数**。小数が欲しいときはどちらかを numeric にする（`7::numeric / 2`）
- 0 で割るとエラー（division by zero）
- 平方根は演算子 `|/` か関数 `sqrt()`

### 文字列の連結

- **`||`** で連結: `'Postgre' || 'SQL'` → `'PostgreSQL'`
- ⚠ **`||` は片方が NULL だと結果も NULL**
- **`concat('a', NULL, 'b')`** → `'ab'`（**NULL を無視**する）。`concat_ws(',', 'a', 'b')` は区切り文字付き

### 型変換（キャスト）

| 書き方 | 例 |
|---|---|
| **`CAST(値 AS 型)`**（SQL 標準） | `CAST('123' AS integer)` |
| **`値::型`**（PostgreSQL 独自） | `'123'::integer` |
| **`型 '文字列'`**（定数のみ） | `date '2026-10-19'` |

- 変換できない値はエラー（`'abc'::integer` → invalid input syntax）
- ⚠ `'1.5'::integer` は**エラー**（文字列から直接は小数を整数にできない）。`1.5::integer` は数値からの変換なので**四捨五入して 2**

| 関数 | 例 | 結果 |
|---|---|---|
| **length(s)** / **char_length(s)** | `length('データ')` | **3**（**文字数**） |
| **octet_length(s)** | `octet_length('データ')` | **9**（**バイト数**。UTF-8 で日本語は1文字3バイト） |
| **upper(s)** / **lower(s)** | `upper('abc')` | 'ABC' |
| initcap(s) | `initcap('hello world')` | 'Hello World' |
| **substring(s FROM n FOR m)** | `substring('PostgreSQL' FROM 5 FOR 3)` | 'gre' |
| **substr(s, n, m)** | `substr('PostgreSQL', 5, 3)` | 'gre' |
| left(s, n) / right(s, n) | `left('PostgreSQL', 4)` | 'Post' |
| **position(t IN s)** / **strpos(s, t)** | `position('SQL' IN 'PostgreSQL')` | 8（見つからなければ **0**） |
| **trim(s)** | `trim('  abc  ')` | 'abc'（両端の空白を除く） |
| ltrim / rtrim / btrim | `ltrim('xxabc', 'x')` | 'abc'（指定した文字を除く） |
| **replace(s, from, to)** | `replace('a-b-c', '-', '/')` | 'a/b/c' |
| **lpad(s, n, c)** / rpad | `lpad('42', 5, '0')` | '00042' |
| split_part(s, 区切り, n) | `split_part('a,b,c', ',', 2)` | 'b' |

- ⚠ 文字の位置は **1 から**数える（0 始まりではない）
- ⚠ `length` は**文字数**、`octet_length` は**バイト数**
- `trim(LEADING 'x' FROM s)`（先頭）、`trim(TRAILING ...)`（末尾）、`trim(BOTH ...)`（両端）の書き方もある

## 4. 日付・時刻関数 ★★★

### 現在日時

| 関数 | 返す値 |
|---|---|
| **current_date** | 今日の日付（date） |
| **current_time** | 現在時刻（time with time zone） |
| **current_timestamp** / **now()** | **トランザクション開始時刻**（timestamptz） |
| localtimestamp | トランザクション開始時刻（timestamp。タイムゾーンなし） |
| statement_timestamp() | **文の開始時刻** |
| **clock_timestamp()** | **関数を呼んだ瞬間**の実時刻（同じ文の中でも変わる） |

- ⚠ `current_date`・`current_timestamp` などは**括弧を付けない**（`current_date()` はエラー）。`now()` は括弧が要る
- ⚠ **now() / current_timestamp は1つのトランザクションの中では何度呼んでも同じ値**。実時刻が欲しいときは clock_timestamp()

### 日時の計算

| 計算 | 結果の型 | 例 |
|---|---|---|
| **date + integer** | date | `date '2026-10-19' + 7` → 2026-10-26 |
| **date - date** | **integer（日数）** | `date '2026-12-26' - date '2026-10-19'` → 68 |
| date + interval | timestamp | `date '2026-10-19' + interval '1 month'` → 2026-11-19 00:00:00 |
| timestamp - timestamp | **interval** | → '2 days 03:00:00' など |
| timestamp ± interval | timestamp | `now() - interval '1 hour'` |

### 日時を扱う関数

| 関数 | 例 | 結果 |
|---|---|---|
| **extract(field FROM t)** | `extract(year FROM date '2026-10-19')` | 2026 |
| **date_part('field', t)** | `date_part('month', date '2026-10-19')` | 10 |
| **date_trunc('field', t)** | `date_trunc('month', timestamp '2026-10-19 09:30')` | 2026-10-01 00:00:00（**指定単位未満を切り捨て**） |
| **age(t1, t2)** | `age(date '2026-10-19', date '2000-04-01')` | 26 years 6 mons 18 days（t1 − t2） |
| age(t) | `age(date '2000-04-01')` | current_date（今日の0時）からの経過 |
| **to_char(t, 書式)** | `to_char(now(), 'YYYY/MM/DD HH24:MI')` | '2026/10/19 09:30' |
| **to_date(s, 書式)** | `to_date('20261019', 'YYYYMMDD')` | date 型の 2026-10-19 |
| to_timestamp(s, 書式) | `to_timestamp('2026-10-19 09:30', 'YYYY-MM-DD HH24:MI')` | timestamptz |
| to_number(s, 書式) | `to_number('1,234', '9,999')` | 1234 |

- extract / date_part の主な field: `year`、`month`、`day`、`hour`、`minute`、`second`、**`dow`（曜日。日曜 = 0）**、`doy`（年内の日数）、`epoch`（1970-01-01 からの秒数）
- 書式の主な記号: **`YYYY`**（年）、**`MM`**（月）、**`DD`**（日）、**`HH24`**（24時間制の時）、`HH` / `HH12`（12時間制）、**`MI`**（分）、**`SS`**（秒）
- ⚠ 分は **`MI`**。`MM` は**月**（取り違えの引っ掛け）

## 5. NULL・条件を扱う関数 ★★★

| 関数 | 動作 | 例 |
|---|---|---|
| **COALESCE(a, b, ...)** | 引数のうち**最初の NULL でない値** | `COALESCE(NULL, NULL, 3)` → 3 |
| **NULLIF(a, b)** | a = b なら **NULL**、違えば a | `NULLIF(0, 0)` → NULL |
| **GREATEST(a, b, ...)** | 最大値 | `GREATEST(3, NULL, 5)` → 5 |
| **LEAST(a, b, ...)** | 最小値 | `LEAST(3, NULL, 5)` → 3 |

- 典型例: NULL を 0 として表示 → `COALESCE(price, 0)`
- 典型例: 0 除算の回避 → `total / NULLIF(cnt, 0)`（cnt が 0 なら NULL を返し、エラーにならない）
- ⚠ PostgreSQL の GREATEST / LEAST は **NULL を無視**する（全部 NULL のときだけ NULL）

## 6. 集約関数（補足）★

## 8. トランザクションの基本 ★★★

### 開始・確定・取り消し

| 操作 | コマンド（同じ意味の別名） |
|---|---|
| 開始 | **BEGIN** / START TRANSACTION |
| 確定 | **COMMIT** / END |
| 取り消し | **ROLLBACK** / ABORT |

- psql は**デフォルトで自動コミット**（AUTOCOMMIT が on）: BEGIN しなければ**1文ごとに自動で COMMIT** される
- psql で `\set AUTOCOMMIT off` にすると、最初の文で自動的にトランザクションが始まり、COMMIT するまで確定しない
- トランザクション外で COMMIT / ROLLBACK を実行してもエラーにならない（WARNING: there is no transaction in progress）

### エラーが起きたとき

```
BEGIN;
INSERT INTO t VALUES (1);
INSERT INTO t VALUES ('abc');   -- エラー
INSERT INTO t VALUES (2);
-- ERROR:  current transaction is aborted, commands ignored until end of transaction block
COMMIT;                          -- 実際には ROLLBACK される（1 も入らない）
```

- ⚠ トランザクション内でエラーが起きると、以降の文は**すべて拒否**される（アボート状態）
- ⚠ この状態で **COMMIT しても ROLLBACK になる**（表示も `ROLLBACK`）。エラー前の文も含めて全部取り消される
- 抜け出すには ROLLBACK（またはセーブポイントへのロールバック）

### セーブポイント

```sql
BEGIN;
INSERT INTO t VALUES (1);
SAVEPOINT sp1;
INSERT INTO t VALUES (2);
ROLLBACK TO SAVEPOINT sp1;   -- 2 の INSERT だけ取り消す（SAVEPOINT は省略可）
INSERT INTO t VALUES (3);
COMMIT;                      -- 1 と 3 が確定
```

- **SAVEPOINT 名前**: トランザクション内に中間地点を作る
- **ROLLBACK TO [SAVEPOINT] 名前**: その地点まで戻す。**トランザクションは続く**（セーブポイント自体も残る）
- **RELEASE [SAVEPOINT] 名前**: セーブポイントを破棄する（それまでの変更は取り消されない）
- エラーでアボート状態になっても、エラー前のセーブポイントへ ROLLBACK TO すれば続行できる
- ⚠ セーブポイントは**トランザクションブロックの中でしか使えない**

### トランザクションと DDL

- PostgreSQL では **CREATE TABLE・DROP TABLE・TRUNCATE などの DDL もロールバックできる**
- ⚠ 例外: **CREATE DATABASE / DROP DATABASE**、CREATE TABLESPACE / DROP TABLESPACE、**VACUUM**、ALTER SYSTEM、CREATE INDEX CONCURRENTLY は**トランザクションブロック内で実行できない**（エラー）
- ⚠ シーケンスの nextval は**ロールバックしても戻らない**（→ 03章）

## 9. トランザクション分離レベル ★★★

### 同時実行で起きる現象

| 現象 | 内容 |
|---|---|
| **ダーティリード** | 他のトランザクションが**コミットしていない**変更が読めてしまう |
| **ノンリピータブルリード**（反復不能読み取り） | 同じ行を2回読むと、間に他がコミットした**更新・削除**のせいで値が変わる |
| **ファントムリード** | 同じ条件で2回検索すると、間に他がコミットした**追加**のせいで行が増える（減る） |
| **直列化異常** | 同時に実行した結果が、どの順番で1つずつ実行した結果とも一致しない |

### 分離レベルと PostgreSQL の動作

| 分離レベル | ダーティリード | ノンリピータブルリード | ファントムリード | 直列化異常 |
|---|---|---|---|---|
| READ UNCOMMITTED | **起きない**（※） | 起きる | 起きる | 起きる |
| **READ COMMITTED**（**デフォルト**） | 起きない | 起きる | 起きる | 起きる |
| **REPEATABLE READ** | 起きない | 起きない | **起きない**（※） | 起きる |
| **SERIALIZABLE** | 起きない | 起きない | 起きない | 起きない |

- ⚠ **PostgreSQL のデフォルトは READ COMMITTED**
- ⚠ ※ PostgreSQL では **READ UNCOMMITTED を指定しても READ COMMITTED として動く**（ダーティリードは**どのレベルでも起きない**）
- ⚠ ※ SQL 標準では REPEATABLE READ でファントムリードが起きてもよいが、**PostgreSQL の REPEATABLE READ では起きない**
- **READ COMMITTED**: **文ごと**に、その文の開始時点でコミット済みのデータを見る
- **REPEATABLE READ / SERIALIZABLE**: トランザクション内の**最初の文**の開始時点のデータをずっと見る
- REPEATABLE READ / SERIALIZABLE では、他と競合すると「could not serialize access ...」のエラーになる → アプリ側で**トランザクションを最初からやり直す**

### 設定方法

```sql
BEGIN ISOLATION LEVEL SERIALIZABLE;              -- 開始時に指定
-- または
BEGIN;
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ; -- 最初の文より前に実行
```

- ⚠ `SET TRANSACTION` は、トランザクション内で **SELECT や INSERT などを実行した後では変更できない**（エラー）
- セッション全体のデフォルト: `SET SESSION CHARACTERISTICS AS TRANSACTION ISOLATION LEVEL ...;` またはパラメータ **default_transaction_isolation**（postgresql.conf でも設定可）
- 確認: `SHOW transaction_isolation;`

## 10. ロック ★★

### MVCC とロックの関係

- PostgreSQL は MVCC なので、**読み取り（SELECT）と書き込み（UPDATE など）は互いを待たない**
- **同じ行を2つのトランザクションが更新**しようとすると、後の方は先の方がコミット / ロールバックするまで**待たされる**（行ロック）
- ⚠ ただし **ACCESS EXCLUSIVE ロック**（DROP TABLE・TRUNCATE・VACUUM FULL・多くの ALTER TABLE）は **SELECT もブロック**する

### 主なテーブルロックのモード

| ロックモード | 取得する主なコマンド |
|---|---|
| ACCESS SHARE | **SELECT** |
| ROW SHARE | SELECT ... FOR UPDATE / FOR SHARE |
| ROW EXCLUSIVE | **INSERT・UPDATE・DELETE** |
| SHARE UPDATE EXCLUSIVE | **VACUUM**（FULL なし）、ANALYZE、CREATE INDEX CONCURRENTLY |
| SHARE | **CREATE INDEX**（CONCURRENTLY なし） |
| SHARE ROW EXCLUSIVE | CREATE TRIGGER など |
| EXCLUSIVE | REFRESH MATERIALIZED VIEW CONCURRENTLY |
| **ACCESS EXCLUSIVE** | **DROP TABLE、TRUNCATE、VACUUM FULL、ALTER TABLE（多く）**、LOCK TABLE（モード省略時） |

- 下に行くほど強い。ACCESS EXCLUSIVE は**他のすべてのロックと競合**する
- ⚠ CREATE INDEX（SHARE）は**書き込みを止める**が読み取りは止めない。書き込みも止めたくないときは CONCURRENTLY

### 明示的なロック

- **`LOCK TABLE t IN 〜 MODE;`**: テーブルロックを取る。モードを省略すると **ACCESS EXCLUSIVE**
  - ⚠ **トランザクションブロックの中でしか使えない**。ロックは**トランザクション終了時に解放**される（個別に解放する UNLOCK コマンドはない）
- **`SELECT ... FOR UPDATE`**: 読んだ行に更新用の行ロックをかける（他は更新・削除・FOR UPDATE できず待つ）
  - `FOR SHARE`: 共有ロック（他の FOR SHARE は可、更新は不可）
  - **`NOWAIT`**: ロックが取れなければ**待たずにエラー**
  - **`SKIP LOCKED`**: ロックされている行を**飛ばして**返す

### デッドロック

- 2つのトランザクションが**互いに相手のロック解放を待つ**状態
- PostgreSQL は**自動で検出**し、**片方のトランザクションをエラーにしてロールバック**させる（もう片方は続行できる）
- 検出のチェックを始めるまでの待ち時間はパラメータ **deadlock_timeout**（デフォルト **1秒**）
- 防ぐには、複数の行・テーブルを**同じ順番で**ロックするようにする
- 現在のロックの状況はシステムビュー **pg_locks** で確認できる
