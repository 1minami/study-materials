# 設定ファイル

> S2.3 設定ファイル（重要度5）。5問前後。パラメータの**反映方法（再起動か再読み込みか）**、主要パラメータのデフォルト値、pg_hba.conf の書式と評価順が定番。

## 1. 設定ファイルの種類 ★★★

| ファイル | 役割 |
|---|---|
| **postgresql.conf** | サーバの**動作パラメータ**（メモリ・接続・ログ・WAL など） |
| **postgresql.auto.conf** | **ALTER SYSTEM** で変更した値が書かれる。postgresql.conf より**後に読まれ優先**される。**手で編集しない** |
| **pg_hba.conf** | **クライアント認証**（どこから・誰が・どの DB に・どの方式で接続できるか） |
| pg_ident.conf | ident / peer 認証で使う、**OS ユーザー名と DB ユーザー名の対応表**（マップ） |

- いずれも既定ではデータディレクトリ直下にある。場所はパラメータ `config_file`、`hba_file`、`ident_file` で変えられる
- 場所の確認: `SHOW config_file;`、`SHOW hba_file;`、`SHOW data_directory;`

## 2. postgresql.conf の書式 ★★

```
# コメント
listen_addresses = '*'        # 文字列は単引用符で囲む
port = 5432
shared_buffers = 256MB        # 単位付きで書ける
log_min_duration_statement = 1s
autovacuum = on
```

- **`パラメータ名 = 値`**（`=` は省略可）。**`#` 以降はコメント**
- パラメータ名は**大文字・小文字を区別しない**
- ⚠ 同じパラメータを複数回書くと**最後に書いたもの**が有効
- 行頭を `#` でコメントアウトした（書かれていない）パラメータは**デフォルト値**になる
- 値の型
  - 真偽値: **on / off**、true / false、yes / no、1 / 0
  - メモリの単位: **kB、MB、GB、TB**（1024 倍。**大文字・小文字を区別**する。`mb` は不可）
  - 時間の単位: **us、ms、s、min、h、d**
  - 単位を省略すると、パラメータごとに決まった単位（例: shared_buffers は 8kB ブロック、work_mem は kB）
- 別ファイルの取り込み: **`include 'ファイル'`**、`include_if_exists 'ファイル'`（無くてもエラーにしない）、`include_dir 'ディレクトリ'`（中の `.conf` を名前順に読む）

## 3. パラメータの反映方法 ★★★

### context（変更できるタイミング）

| context | 変更の反映 | 例 |
|---|---|---|
| **postmaster** | **サーバの再起動**が必要 | listen_addresses、port、max_connections、shared_buffers、wal_level、archive_mode、logging_collector |
| **sighup** | **設定の再読み込み**（reload）で反映。セッション内の SET は不可 | log_*（多く）、archive_command、autovacuum、checkpoint_timeout、**pg_hba.conf の内容** |
| superuser | スーパーユーザーなら SET で変更できる | log_statement、log_min_duration_statement |
| **user** | **一般ユーザーも SET で変更**できる | work_mem、search_path、client_encoding、default_transaction_isolation、TimeZone |
| backend / superuser-backend | 接続開始時にだけ設定できる | log_connections（superuser-backend） |
| internal | 変更不可（ビルド時に決まる） | block_size、server_version |

- 確認: **`SELECT name, setting, unit, context FROM pg_settings;`**
- pg_settings の **pending_restart** 列: 設定ファイルは変えたが**再起動しないと反映されない**パラメータが true になる
- ⚠ **pg_hba.conf の変更は再読み込み（reload）で反映**される（再起動は不要）

### 再読み込みの方法

| 方法 | |
|---|---|
| **`pg_ctl reload`** | OS のコマンドから |
| **`SELECT pg_reload_conf();`** | SQL から（スーパーユーザーなど） |
| `kill -HUP <postmaster の PID>` | シグナルを直接送る |
| `systemctl reload postgresql-14` | パッケージ版のサービスから |

- ⚠ 再読み込みで postmaster のパラメータを変えても**反映されない**（ログに「再起動が必要」と出る）

## 4. SQL からの設定変更 ★★★

### セッション単位: SET / SHOW / RESET

```sql
SET work_mem = '64MB';            -- このセッションだけ変更（TO も可: SET work_mem TO '64MB'）
SHOW work_mem;                    -- 現在値を表示
SHOW ALL;                         -- 全パラメータ
RESET work_mem;                   -- デフォルト（設定ファイルの値）に戻す
SET LOCAL work_mem = '128MB';     -- このトランザクションの間だけ変更
SELECT current_setting('work_mem');          -- 関数で取得
SELECT set_config('work_mem', '32MB', false); -- 関数で設定（true ならトランザクション内だけ）
```

- ⚠ SET の効果は**そのセッションだけ**。切断すると消え、他のセッションには影響しない
- ⚠ **SET LOCAL** はトランザクションの終了で元に戻る。トランザクション外で使うと警告が出て効果なし
- トランザクション内で SET した後に **ROLLBACK すると SET も取り消される**

### 永続的な変更: ALTER SYSTEM

```sql
ALTER SYSTEM SET work_mem = '16MB';   -- postgresql.auto.conf に書き込む
SELECT pg_reload_conf();              -- 反映（postmaster のパラメータなら再起動）
ALTER SYSTEM RESET work_mem;          -- auto.conf から削除
ALTER SYSTEM RESET ALL;
```

- **スーパーユーザー**だけが実行できる
- ⚠ ALTER SYSTEM は**ファイルに書くだけ**。**反映には再読み込みか再起動が必要**
- ⚠ **トランザクションブロック内では実行できない**
- ⚠ postgresql.auto.conf は postgresql.conf より後に読まれるので、**同じパラメータは auto.conf の値が勝つ**

### データベース単位・ロール単位

```sql
ALTER DATABASE sampledb SET work_mem = '32MB';
ALTER ROLE alice SET search_path = 'app, public';
ALTER ROLE alice IN DATABASE sampledb SET work_mem = '64MB';
ALTER ROLE alice RESET work_mem;
```

- **次に接続したセッションから**有効（今のセッションには効かない）
- 設定値の優先順位（後ろほど優先）

```
postgresql.conf → postgresql.auto.conf → サーバ起動オプション（postgres -c）
  → ALTER DATABASE ... SET → ALTER ROLE ... SET → ALTER ROLE ... IN DATABASE ... SET
  → クライアントの接続オプション（PGOPTIONS） → セッション内の SET
```

## 5. 主要パラメータ ★★★

### 接続

| パラメータ | デフォルト | context | 意味 |
|---|---|---|---|
| **listen_addresses** | **'localhost'** | postmaster | 接続を待ち受ける IP アドレス。**`'*'` で全インターフェース**。空文字列で TCP/IP を受け付けない |
| **port** | **5432** | postmaster | ポート番号 |
| **max_connections** | **100** | postmaster | 同時接続数の上限 |
| superuser_reserved_connections | 3 | postmaster | max_connections のうち**スーパーユーザー用に予約**する数 |
| unix_socket_directories | '/tmp'（ビルドによる） | postmaster | Unix ドメインソケットの場所 |
| password_encryption | **scram-sha-256** | user | パスワードの保存形式（**14 から scram-sha-256**。13 までは md5） |

- ⚠ **デフォルトの listen_addresses は localhost**: 他のマシンから接続するには、**listen_addresses の変更（再起動）と pg_hba.conf への許可の追加（再読み込み）の両方**が必要

### メモリ

| パラメータ | デフォルト | context | 意味 |
|---|---|---|---|
| **shared_buffers** | **128MB** | postmaster | 全プロセスで共有する**データのキャッシュ**（共有バッファ）。物理メモリの 25% 程度が目安 |
| **work_mem** | **4MB** | user | **1回のソート・ハッシュ操作**が使うメモリ。超えると一時ファイルを使う |
| **maintenance_work_mem** | **64MB** | user | **VACUUM、CREATE INDEX** などメンテナンス作業用のメモリ |
| effective_cache_size | 4GB | user | プランナが想定する OS のキャッシュを含めたキャッシュ量（実際には確保しない） |
| wal_buffers | -1（自動） | postmaster | WAL を書き出す前のバッファ |

- ⚠ work_mem は**接続ごと・操作ごと**に確保される。大きくしすぎると、同時接続が多いときにメモリ不足になる

### WAL・チェックポイント

| パラメータ | デフォルト | context | 意味 |
|---|---|---|---|
| **wal_level** | **replica** | postmaster | WAL に書く情報量。**minimal** < **replica**（アーカイブ・レプリケーションに必要）< **logical**（論理レプリケーション） |
| **fsync** | **on** | sighup | 更新をディスクへ確実に書き出す。**off にするとクラッシュでデータが壊れうる** |
| **synchronous_commit** | **on** | user | コミット時に **WAL のディスク書き込みを待つ**か。off なら速いが、クラッシュ時に直前のコミットが失われうる（**不整合にはならない**） |
| checkpoint_timeout | **5min** | sighup | 自動チェックポイントの間隔 |
| **max_wal_size** | **1GB** | sighup | この量の WAL がたまるとチェックポイントを実行 |
| min_wal_size | 80MB | sighup | 再利用のために残しておく WAL 量 |
| checkpoint_completion_target | 0.9 | sighup | チェックポイントの書き出しを間隔のどの割合まで分散させるか |
| **archive_mode** | **off** | postmaster | WAL アーカイブを有効にする（→ 07章） |
| **archive_command** | ''（空） | sighup | WAL ファイルをアーカイブするシェルコマンド（→ 07章） |
| max_wal_senders | 10 | postmaster | WAL 送信プロセス（レプリケーション・pg_basebackup）の上限 |

- **チェックポイント**: 共有バッファ上の変更済みページ（ダーティページ）を**データファイルへ書き出す**処理。それ以前の WAL はクラッシュリカバリに不要になる。**`CHECKPOINT`** コマンドで手動実行もできる
- ⚠ fsync = off と synchronous_commit = off の違い: **fsync off はデータ破損のおそれ**、synchronous_commit off は**直近のコミットを失うおそれ（整合性は保たれる）**

### ログ

| パラメータ | デフォルト | 意味 |
|---|---|---|
| **logging_collector** | **off** | ログ収集プロセスを使い、ログを**ファイルに**書く（postmaster。変更は再起動） |
| **log_destination** | **'stderr'** | 出力先。stderr、**csvlog**（logging_collector が必要）、**syslog**、eventlog（Windows） |
| **log_directory** | **'log'** | ログファイルを置くディレクトリ（相対パスはデータディレクトリから） |
| **log_filename** | 'postgresql-%Y-%m-%d_%H%M%S.log' | ログファイル名（strftime の書式） |
| log_rotation_age / log_rotation_size | 1d / 10MB | ログファイルを切り替える時間 / サイズ |
| **log_min_messages** | **warning** | **サーバログに出す最低レベル** |
| client_min_messages | notice | **クライアントに返す**最低レベル |
| **log_min_duration_statement** | **-1**（無効） | **指定時間以上かかった SQL** をログに出す（0 で全 SQL）。スロークエリの調査に使う |
| **log_statement** | **none** | SQL をログに出す範囲: **none / ddl / mod / all** |
| log_line_prefix | '%m [%p] ' | 各行の先頭に付ける情報（%m = 時刻、%p = PID、%u = ユーザー、%d = DB） |
| log_connections / log_disconnections | off | 接続・切断をログに出す |
| log_lock_waits | off | deadlock_timeout を超えたロック待ちをログに出す |

- メッセージのレベル（低 → 高）: DEBUG5〜DEBUG1 → INFO → **NOTICE** → **WARNING** → **ERROR** → LOG → **FATAL** → **PANIC**
  - log_min_messages で指定したレベル**以上**が出力される（サーバログでは LOG は ERROR より上の扱い）
- ⚠ log_statement の **mod** は ddl に加えて **INSERT・UPDATE・DELETE・TRUNCATE** なども出す（「ddl ⊂ mod ⊂ all」）

### クライアント接続時のデフォルト

| パラメータ | デフォルト | 意味 |
|---|---|---|
| **search_path** | **'"$user", public'** | スキーマの検索順（→ 03章） |
| **client_encoding** | DB のエンコーディング | クライアント側の文字コード（サーバ側で自動変換） |
| **default_transaction_isolation** | **'read committed'** | 分離レベルのデフォルト（→ 04章） |
| **TimeZone** | initdb 時の OS の設定 | タイムゾーン |
| DateStyle | 'ISO, MDY'（initdb で決まる） | 日付の表示形式 |
| lc_messages | initdb 時のロケール | メッセージの言語 |
| statement_timeout | 0（無効） | 指定時間を超えた SQL を中断する |
| deadlock_timeout | 1s | デッドロック検出を始めるまでの待ち時間（→ 04章） |

### autovacuum

- autovacuum（デフォルト **on**）、autovacuum_naptime（**1min**）など → 08章

## 6. pg_hba.conf（クライアント認証） ★★★

### 書式

```
# TYPE    DATABASE   USER       ADDRESS           METHOD
local     all        postgres                     peer
local     all        all                          scram-sha-256
host      all        all        127.0.0.1/32      scram-sha-256
host      sampledb   +staff     192.168.1.0/24    scram-sha-256
hostssl   all        all        0.0.0.0/0         scram-sha-256
host      all        all        ::1/128           scram-sha-256
host      replication  repuser  192.168.1.20/32   scram-sha-256
host      all        all        0.0.0.0/0         reject
```

- 1行1ルール。**`接続タイプ データベース ユーザー [アドレス] 認証方式 [オプション]`**
- **上から順に評価し、最初に一致した行だけを使う**
- ⚠ 一致した行の認証に**失敗しても、次の行は試さない**（そのまま接続拒否）
- ⚠ **どの行にも一致しなければ拒否**
- ⚠ 書く順番が大事: 例外的なルール（特定ユーザーの許可・拒否）は**上**に、一般的なルールは**下**に書く
- 変更は **再読み込み（pg_ctl reload / pg_reload_conf()）** で反映
- 中身の確認: システムビュー **pg_hba_file_rules**（書式エラーの行も分かる）

### 接続タイプ（TYPE）

| タイプ | 対象 |
|---|---|
| **local** | **Unix ドメインソケット**の接続（アドレス欄は書かない） |
| **host** | **TCP/IP** の接続（SSL・非 SSL の**両方**） |
| **hostssl** | TCP/IP のうち **SSL を使う**接続だけ |
| **hostnossl** | TCP/IP のうち **SSL を使わない**接続だけ |
| hostgssenc / hostnogssenc | GSSAPI 暗号化の有無 |

- ⚠ `psql -h localhost` は **TCP/IP（host 行）**、`-h` なしは **Unix ドメインソケット（local 行）** になる

### データベース（DATABASE）とユーザー（USER）

| 書き方 | 意味 |
|---|---|
| **all** | すべて。⚠ DATABASE の all に **replication は含まれない** |
| **sameuser** | **ユーザー名と同じ名前**のデータベース |
| samerole | ユーザーが**同名のロールのメンバー**であるデータベース |
| **replication** | **物理レプリケーション接続**（pg_basebackup など） |
| 名前 | そのデータベース / ユーザー。カンマ区切りで複数可 |
| **`+ロール名`**（USER 欄） | **そのロールのメンバー**全員 |
| `@ファイル名` | ファイルに書いた名前の一覧 |

### アドレス（ADDRESS）

- **CIDR 形式**: `192.168.1.0/24`（ネットワーク）、`192.168.1.10/32`（1台）、`0.0.0.0/0`（IPv4 すべて）、`::1/128`（IPv6 のループバック）
- IP アドレスとネットマスクを2列に分けて書いてもよい（`192.168.1.0 255.255.255.0`）
- **samehost**（サーバ自身のアドレス）、**samenet**（サーバと同じサブネット）、ホスト名も書ける

### 認証方式（METHOD）

| 方式 | 動作 |
|---|---|
| **trust** | **無条件で許可**（パスワード不要） |
| **reject** | **無条件で拒否** |
| **scram-sha-256** | **SCRAM-SHA-256 のパスワード認証**（最も安全なパスワード方式） |
| **md5** | MD5 のチャレンジ・レスポンス認証。保存されたパスワードが SCRAM 形式なら**自動で SCRAM 認証**になる |
| **password** | パスワードを**平文で**送る（SSL なしでは非推奨） |
| **peer** | **OS のユーザー名**をカーネルから取得し、DB ユーザー名と同じなら許可。**local 接続専用** |
| **ident** | ident サーバに問い合わせて OS ユーザー名を得る（**TCP/IP 用**。local 指定時は peer になる） |
| ldap / radius / pam / gss / sspi / cert | 外部の認証基盤・証明書による認証 |

- ⚠ **trust はパスワードなしで誰でも入れる**。initdb のデフォルト（-A 省略時）は trust
- ⚠ md5 方式でも、**password_encryption = scram-sha-256（14 のデフォルト）で設定したパスワードなら SCRAM で認証される**。逆に、**MD5 形式で保存されたパスワードは scram-sha-256 方式では認証できない**
- ⚠ **peer は local 接続でしか使えない**
- オプション: `map=マップ名` で **pg_ident.conf** のマップを使い、OS ユーザー名と違う DB ユーザー名を許可できる

```
# pg_ident.conf
# MAPNAME   SYSTEM-USERNAME   PG-USERNAME
mymap       taro              app_user
```

```
# pg_hba.conf
local   all   app_user   peer   map=mymap
```
