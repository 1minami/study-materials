# バックアップ

> S2.4 バックアップ方法（重要度**7**）。7問前後で、運用管理で最大の山。pg_dump の出力形式とリストア方法の組み合わせ、COPY と \copy の違い、PITR の手順が定番。

## 1. バックアップ方法の全体像 ★★★

| 方法 | 種類 | サーバ | 単位 | 主なツール |
|---|---|---|---|---|
| **論理バックアップ** | SQL やデータの形でダンプ | **起動したまま** | **データベース / テーブル** | **pg_dump**、**pg_dumpall** |
| **物理バックアップ（オフライン）** | データディレクトリのファイルをコピー | **停止して** | **クラスタ全体** | cp、tar、rsync |
| **物理バックアップ（オンライン）** | 起動したままファイルをコピー | **起動したまま** | **クラスタ全体** | **pg_basebackup**、低レベル API |
| **PITR** | オンライン物理バックアップ + **WAL アーカイブ** | 起動したまま | クラスタ全体 | 上記 + archive_command |
| COPY | テーブルのデータだけをファイルへ | 起動したまま | テーブル | COPY、\copy |

- ⚠ **論理バックアップは別のメジャーバージョン・別の OS / CPU アーキテクチャへ移せる**。物理バックアップは**同じメジャーバージョン・同じアーキテクチャ**でしか使えない
- ⚠ **論理バックアップは取得した時点にしか戻せない**。任意の時点に戻せるのは **PITR**
- 物理バックアップは**テーブル単位では戻せない**（クラスタ全体を戻す）

## 2. pg_dump ★★★

```
pg_dump [接続オプション] [オプション] データベース名
```

- **1つのデータベース**を論理バックアップする。**サーバを起動したまま**取得でき、取得中も他のユーザーは**読み書きできる**
- 取得開始時点の**一貫したスナップショット**を出力する（途中の更新は含まない）
- ⚠ pg_dump は対象テーブルに ACCESS SHARE ロックを取るので、取得中は **DROP TABLE や ALTER TABLE など（ACCESS EXCLUSIVE）が待たされる**
- 実行するユーザーには対象の**読み取り権限**が必要（通常はスーパーユーザーで実行）

### 出力形式（-F）

| オプション | 形式 | リストア方法 | 特徴 |
|---|---|---|---|
| **`-Fp`**（**デフォルト**） | **プレーンテキスト**（SQL スクリプト） | **psql** | 中身を読める・編集できる |
| **`-Fc`** | **カスタム形式** | **pg_restore** | **デフォルトで圧縮**。リストア時にオブジェクトを選べる・並べ替えられる |
| **`-Fd`** | **ディレクトリ形式** | **pg_restore** | テーブルごとにファイル。**並列ダンプ（-j）できる唯一の形式** |
| **`-Ft`** | **tar 形式** | **pg_restore** | 圧縮はできない |

- ⚠ **プレーンテキストは pg_restore では戻せない**（psql で流す）。**それ以外の3形式は psql では戻せない**（pg_restore を使う）
- ⚠ **pg_dump の並列実行（-j）はディレクトリ形式だけ**。pg_restore の -j は**カスタム形式とディレクトリ形式**で使える

### 主なオプション

| オプション | 意味 |
|---|---|
| **`-f ファイル`** | 出力先（省略時は**標準出力**。ディレクトリ形式では必須） |
| **`-F 形式`** | 出力形式（p / c / d / t） |
| **`-t テーブル`** / `-T テーブル` | そのテーブルだけ / そのテーブルを除いて出力 |
| **`-n スキーマ`** / `-N スキーマ` | そのスキーマだけ / 除いて出力 |
| **`-s`** / `--schema-only` | **定義（スキーマ）だけ**出力（データなし） |
| **`-a`** / `--data-only` | **データだけ**出力（定義なし） |
| **`-c`** / `--clean` | オブジェクトを作る前に **DROP 文**を出力 |
| **`-C`** / `--create` | **CREATE DATABASE 文**とその DB への接続（`\connect`）を出力 |
| `--if-exists` | -c の DROP に IF EXISTS を付ける |
| **`--inserts`** / `--column-inserts` | データを COPY ではなく **INSERT 文**で出力（遅いが他の DBMS へ移しやすい） |
| `-O` / `--no-owner` | 所有者を設定する文を出力しない |
| `-x` / `--no-privileges` | GRANT / REVOKE を出力しない |
| `-Z 0〜9` | 圧縮レベル |
| **`-j 数`** | 並列数（**-Fd のみ**） |

- ⚠ **-s（schema-only）の「schema」はスキーマ（名前空間）ではなく「定義」**。スキーマを選ぶのは **-n**
- ⚠ データはデフォルトで **COPY 文**として出力される

### pg_dump が出力しないもの

- ⚠ **ロール（ユーザー）とテーブルスペース**は**クラスタ全体のオブジェクト（グローバルオブジェクト）**なので、**pg_dump では出力されない** → **pg_dumpall** を使う
- データベース自体の作成文（CREATE DATABASE）も、**-C を付けない限り出力しない**

## 3. pg_dumpall ★★★

```
pg_dumpall [接続オプション] [オプション] > all.sql
psql -f all.sql postgres                  # リストア
```

- **クラスタ内のすべてのデータベース**と、**ロール・テーブルスペースなどのグローバルオブジェクト**を出力する
- ⚠ 出力は**プレーンテキストだけ**（-F オプションがない）→ リストアは **psql**
- 各データベースに接続して取得するので、**スーパーユーザー**で実行するのが普通

| オプション | 意味 |
|---|---|
| **`-g`** / `--globals-only` | **グローバルオブジェクト（ロール・テーブルスペース）だけ** |
| **`-r`** / `--roles-only` | **ロールだけ** |
| **`-t`** / `--tablespaces-only` | **テーブルスペースだけ** |
| `-s` / `-a` / `-c` | 定義だけ / データだけ / DROP 文を付ける（pg_dump と同じ） |
| `-f ファイル` | 出力先 |

- ⚠ **pg_dumpall の -t はテーブルスペース**（pg_dump の -t はテーブル）
- よくある組み合わせ: `pg_dumpall -g` でロール等を取り、DB ごとに `pg_dump -Fc` で取る

## 4. リストア（psql と pg_restore） ★★★

### プレーンテキストのリストア

```
psql -d newdb -f sample.sql
psql newdb < sample.sql
```

- 戻し先のデータベースを**先に作っておく**（`createdb newdb`）。ダンプ時に -C を付けていれば、別の DB（postgres など）に接続して流せば CREATE DATABASE から実行される
- psql はエラーが起きても**続行**する。止めたいときは `-v ON_ERROR_STOP=1`、全体を1トランザクションにするなら **`-1`**

### pg_restore

```
pg_restore -d newdb sample.dump              # newdb へ戻す
pg_restore -C -d postgres sample.dump        # DB を作ってから戻す（-d は接続用の既存 DB）
pg_restore -l sample.dump > list.txt         # 中身の一覧（目次）を出力
pg_restore -L list.txt -d newdb sample.dump  # 一覧で選んだものだけ戻す
pg_restore -f out.sql sample.dump            # SQL スクリプトに変換して出力
```

| オプション | 意味 |
|---|---|
| **`-d データベース`** | **接続して戻す先**。⚠ **省略すると SQL を標準出力（または -f のファイル）に出す**だけ |
| **`-C`** | CREATE DATABASE してから戻す（-d には接続用の別 DB を指定） |
| **`-c`** | 戻す前に既存のオブジェクトを DROP する |
| **`-t`** / `-n` / `-I` | 指定したテーブル / スキーマ / インデックスだけ戻す |
| **`-s`** / **`-a`** | 定義だけ / データだけ戻す |
| **`-l`** | アーカイブの**目次を表示** |
| **`-L ファイル`** | 目次ファイルに書かれた項目だけを、その**順番で**戻す |
| **`-j 数`** | **並列リストア**（カスタム形式・ディレクトリ形式） |
| `-1` | 1つのトランザクションで戻す（-j とは併用不可） |

- ⚠ pg_restore は **プレーンテキスト以外**（カスタム・ディレクトリ・tar）専用

## 5. COPY と \copy ★★★

### COPY（サーバ側）

```sql
COPY emp TO '/tmp/emp.csv' WITH (FORMAT csv, HEADER);   -- テーブル → ファイル
COPY emp FROM '/tmp/emp.csv' WITH (FORMAT csv, HEADER); -- ファイル → テーブル（追加）
COPY emp (id, name) TO STDOUT;                          -- 列を指定、標準出力へ
COPY (SELECT * FROM emp WHERE dept = 10) TO '/tmp/d10.txt'; -- 問い合わせ結果を出力
```

- **TO** = テーブルから**書き出す**、**FROM** = テーブルへ**読み込む**
- ⚠ ファイルは**データベースサーバのマシン上**のパス。読み書きするのは**サーバプロセス（OS の postgres ユーザー）**
- ⚠ サーバのファイルを読み書きする COPY は**スーパーユーザー**か、**pg_read_server_files / pg_write_server_files** ロールのメンバーだけが実行できる（STDIN / STDOUT は一般ユーザーも可）
- ⚠ COPY FROM は**追記**（既存の行は消さない）。途中でエラーになると**全行が取り消される**
- `COPY (SELECT ...) TO` で問い合わせ結果を出せる。**COPY (SELECT ...) FROM はできない**
- COPY FROM はトリガーや制約チェックを実行する

### 主なオプション

| オプション | 意味 |
|---|---|
| **FORMAT** | **text**（**デフォルト**）/ **csv** / binary |
| **DELIMITER** | 区切り文字。デフォルトは **text = タブ**、**csv = カンマ** |
| **NULL** | NULL を表す文字列。デフォルトは **text = `\N`**、**csv = 引用符なしの空文字列** |
| **HEADER** | 先頭行を列名の行にする（14 では **csv 形式のみ**） |
| QUOTE / ESCAPE | csv の引用符（デフォルト `"`）/ エスケープ文字 |
| ENCODING | ファイルの文字エンコーディング |

- 古い書き方 `COPY emp TO '/tmp/emp.csv' CSV HEADER;` も使える

### \copy（psql のメタコマンド、クライアント側）

```
\copy emp TO 'emp.csv' WITH (FORMAT csv, HEADER)
\copy emp FROM 'emp.csv' WITH (FORMAT csv, HEADER)
```

- **psql を実行しているクライアントのマシン上**のファイルを読み書きする（内部では COPY ... FROM STDIN / TO STDOUT を使う）
- **スーパーユーザーでなくても**、テーブルの権限があれば使える
- ⚠ メタコマンドなので**1行で書く**（末尾の `;` は不要）

| | COPY | \copy |
|---|---|---|
| 種類 | **SQL コマンド** | **psql のメタコマンド** |
| ファイルの場所 | **サーバ側** | **クライアント側** |
| ファイルを読み書きする OS ユーザー | サーバプロセス（postgres） | psql を実行したユーザー |
| 必要な権限 | スーパーユーザー等（ファイルの場合） | テーブルの権限だけ |

## 6. 物理バックアップ ★★

### オフラインバックアップ（コールドバックアップ）

1. **サーバを停止**する（pg_ctl stop）
2. **データディレクトリ全体**（テーブルスペースを使っていればその実体も）を tar や cp でコピーする
3. サーバを起動する

- ⚠ **起動したまま**データディレクトリを単純コピーしても、一貫したバックアップにはならない
- ⚠ 一部のデータベース・テーブルだけを戻すことはできない（クラスタ全体を戻す）

### pg_basebackup（オンラインバックアップ）

```
pg_basebackup -D /backup/base -Fp -X stream -P -U repuser -h 192.168.1.10
```

- **サーバを起動したまま**、**クラスタ全体**の物理バックアップを取る（**レプリケーション接続**を使う）
- ストリーミングレプリケーションのスタンバイ構築にも使う

| オプション | 意味 |
|---|---|
| **`-D ディレクトリ`** | 出力先（必須）。⚠ 空か存在しないこと |
| **`-F p` / `-F t`** | **plain**（データディレクトリと同じ構成。**デフォルト**）/ **tar** |
| **`-X 方式`** | バックアップ中の WAL の取得方法: **stream**（**デフォルト**。並行して転送）/ fetch（最後にまとめて）/ none |
| **`-z`** | gzip 圧縮（tar 形式） |
| **`-P`** | 進捗を表示 |
| **`-R`** | スタンバイ用の設定（**standby.signal** と、postgresql.auto.conf への **primary_conninfo**）を書き出す |
| `-c fast` / `-c spread` | 開始時のチェックポイントを即時 / 分散（**デフォルト spread**） |
| `-l ラベル` | バックアップのラベル |

- 必要な条件
  - **wal_level が replica 以上**（デフォルトの replica で OK）
  - **max_wal_senders が 1 以上**（デフォルト 10）
  - 接続ロールに **REPLICATION 属性**（またはスーパーユーザー）
  - **pg_hba.conf に DATABASE = `replication` の行**
- ⚠ pg_hba.conf の DATABASE 欄が **all でもレプリケーション接続には一致しない**。`replication` と書く

### 低レベル API（PostgreSQL 14）

```sql
SELECT pg_start_backup('label');   -- バックアップ開始（チェックポイントを実行）
-- この間に OS のコマンドでデータディレクトリをコピー
SELECT pg_stop_backup();           -- バックアップ終了（必要な WAL のアーカイブを待つ）
```

- 開始すると、データディレクトリに **backup_label** ファイル（開始位置などの情報）ができる（排他モードの場合）
- ⚠ **15 で pg_backup_start() / pg_backup_stop() に改名**され、排他モードは廃止。試験（14 基準）は**旧名**で答える

## 7. WAL とアーカイブ ★★★

### WAL の基本

- **WAL（Write Ahead Log、先行書き込みログ）**: データを変更する前に、**変更内容をログに書く**仕組み
- コミット時は WAL をディスクに書けばよく、データファイルへの反映は**チェックポイント**でまとめて行う
- WAL ファイルは **pg_wal/** に置かれ、1ファイル（**WAL セグメント**）は **16MB**（initdb の `--wal-segsize` で変更可）
- ファイル名は **24桁の16進数**（タイムライン ID 8桁 + 論理位置 16桁）。例: `000000010000000000000003`
- WAL 内の位置は **LSN**（Log Sequence Number）。`SELECT pg_current_wal_lsn();` で確認
- 使い終わった WAL は、チェックポイント後に**削除または再利用**される → PITR には**アーカイブ**して残しておく必要がある
- **`SELECT pg_switch_wal();`**: 現在の WAL ファイルを閉じて**次のファイルへ切り替える**（すぐにアーカイブさせたいとき。10 より前は pg_switch_xlog）

### WAL アーカイブの設定（postgresql.conf）

```
wal_level = replica                       # minimal では不可
archive_mode = on                         # 変更は再起動が必要
archive_command = 'cp %p /archive/%f'     # 変更は再読み込みで反映
archive_timeout = 60                      # 任意。この秒数ごとに強制的に WAL を切り替える
```

| 記号 | 意味 |
|---|---|
| **`%p`** | アーカイブする WAL ファイルの**パス**（データディレクトリからの相対パス） |
| **`%f`** | WAL ファイルの**ファイル名だけ** |

- archive_command は **WAL ファイルが一杯になる（切り替わる）たびに**実行される
- ⚠ コマンドが**終了ステータス 0 を返したときだけ成功**とみなす。失敗した WAL は pg_wal に残り、**成功するまで再試行**される（pg_wal があふれるおそれ）
- ⚠ **archive_mode の変更は再起動**、archive_command の変更は**再読み込み**で反映
- アーカイブの状況はシステムビュー **pg_stat_archiver** で確認できる

## 8. PITR（ポイントインタイムリカバリ） ★★★

### 仕組み

- **ベースバックアップ**（オンライン物理バックアップ）を戻し、その後の **アーカイブ WAL を再生（ロールフォワード）** して、**任意の時点**まで復旧する
- 例: 誤って DROP TABLE した**直前の時刻**まで戻せる

### 事前準備

1. **WAL アーカイブを有効**にする（wal_level・archive_mode・archive_command）
2. 定期的に **ベースバックアップ**（pg_basebackup など）を取る

### リカバリの手順（PostgreSQL 12 以降）

1. **サーバを停止**する
2. 現在のデータディレクトリを退避し、**ベースバックアップを戻す**
3. 退避した **pg_wal/ のうち、まだアーカイブされていない WAL** を新しい pg_wal/ にコピーする（最新まで戻すため）
4. **postgresql.conf**（または postgresql.auto.conf）に **restore_command** と、必要なら**リカバリ目標**を書く
5. データディレクトリに **recovery.signal** ファイル（空でよい）を作る
6. **サーバを起動**する → WAL を再生してリカバリ → 完了すると通常運転になる（**recovery.signal は自動で削除**される）

```
restore_command = 'cp /archive/%f %p'          # アーカイブから WAL を取り出すコマンド
recovery_target_time = '2026-11-25 10:29:00'    # この時刻まで戻す
```

- ⚠ **12 以降は recovery.conf が廃止**され、設定は **postgresql.conf** に、リカバリ開始の合図は **recovery.signal** ファイルになった（recovery.conf があると**起動しない**）
- **standby.signal**: リカバリ後もスタンバイとして WAL の再生を続ける（ストリーミングレプリケーション用）
- リカバリが完了すると**新しいタイムライン**が始まる（WAL ファイル名の先頭8桁が増える）。過去の時点に戻した後の歴史を、元の歴史と区別するため

### リカバリ目標のパラメータ

| パラメータ | 意味 |
|---|---|
| **recovery_target_time** | **指定した時刻**まで |
| **recovery_target_xid** | **指定したトランザクション ID** まで |
| **recovery_target_name** | **`pg_create_restore_point('名前')`** で作った**復元ポイント**まで |
| recovery_target_lsn | 指定した LSN まで |
| recovery_target = 'immediate' | ベースバックアップが**一貫性のある状態になった時点**で止める |
| recovery_target_inclusive | 目標の**ちょうどその点を含めるか**（デフォルト **on** = 含める） |
| recovery_target_timeline | どのタイムラインに沿って戻すか（**12 からデフォルト latest**） |
| **recovery_target_action** | 目標に達した後の動作: **pause**（**デフォルト**）/ promote / shutdown |

- ⚠ 目標を何も指定しないと、**アーカイブの最後（最新）まで**再生する
- ⚠ 目標のパラメータは**1つだけ**指定できる（複数書くとエラー）
- pause で止まったら、内容を確認してから **`SELECT pg_wal_replay_resume();`** でリカバリを終えて通常運転にする
