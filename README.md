### ページ内検索

サイドバー最上部（目次の上）に検索ボックスを常設。目次をスクロールしても sticky で残る。

- 対象: **本文（`.chapter` 配下）のみ**。一問一答・4択・穴埋めの問題データは検索しない
- ヒットは黄色、現在位置はオレンジでハイライト。入力欄の下に `3 / 17` カウンタと ↑↓✕ ボタン
- 操作: `Ctrl+F`（Mac は `Cmd+F`）= 検索欄へフォーカス（ブラウザ標準の検索は上書き）/ `Enter` = 次へ / `Shift+Enter` = 前へ / `Esc` or ✕ = クリア（ハイライトを全解除し DOM を元に戻す）
- 大文字小文字は区別しない。日本語 IME は変換確定後に検索が走る（変換中は走らない）。入力は 200ms debounce
- スマホ（768px 以下）: `Ctrl+F` でサイドバーを自動で開く。`Enter` ・↑↓ でヒットへ飛んだときはサイドバーを閉じて本文を見せる
- 制約:
  - **タグを跨いだ語はヒットしない**。教材の `**太字**` は `<strong>` になるため、太字と地の文に割れている箇所は1語として拾えない（単一テキストノード内のマッチのみ対象）
  - ハイライトは **1000件で打ち切り**（カウンタは `1 / 1000+` 表示）。1文字検索でのフリーズを防ぐため
- クイズ系モーダルを開いている間は `Ctrl+F` を奪わず、ブラウザ標準の検索に委ねる
- 実装: `templates/script.js` の「ページ内検索」ブロック / `templates/style.css` の `.toc-search` `mark.search-hit` / markup は `scripts/build_takken_textbook.py` の `build_toc()`

### 読み上げ

本文（00〜18章）の章見出し（h2）・節見出し（h3）横の ▶ を押すと、その位置から**章末まで**連続で読み上げる。Web Speech API（`speechSynthesis`）を使い、音声ファイルは持たない。

- 操作バー（画面下部固定・再生中のみ表示）: ⏮ 前の節 / ⏸▶ 一時停止・再開 / ⏭ 次の節 / ■ 停止 / 速度（0.75〜2x、`localStorage` の `takken-tts-rate` に保存）
- 読み上げ中のブロック（見出し・段落・箇条書き1項目・表1行）をハイライトし、画面外なら自動スクロール
- 表は1行ずつ「列見出し、値。列見出し、値」の形で読む。セルの `○` `×` `△` は「まる」「ばつ」「さんかく」、空・`-` は「なし」
- `★`（頻出度）は読まない。`⚠` は「注意」、`→` は読点に置換。絵文字は除去
- **読み辞書**（`TTS_READINGS`）: 端末音声が誤読する語を、発話する文字列の上だけでカタカナに置換する（例: 供託所→キョウタクショ、買主→カイヌシ、賃貸借→チンタイシャク）。画面の文言・検索・操作バーの見出し表示には影響しない
  - 読みは法律読みに統一（遺言=イゴン、競売=ケイバイ、兄弟姉妹=ケイテイシマイ、立木=リュウボク、何人も=ナンピトモ）
  - 追加方法: `templates/script.js` の `TTS_READINGS` に `語=ヨミ` を空白区切りで足してビルド。長い語から順に照合するので並び順は不問
  - 短い語は別の語の一部に当たらないか確認する（例: `引上` は「取引上」に当たるため `引上げ` で登録）。避けられないときは `優先順位=優先順位` のように「語=同じ語」を足して置換させない
  - 収録語は Windows の Microsoft Haruka に本文 00〜18章を読ませて洗い出したもの（2026-10-10）。Android（Google 音声）固有の誤読は未調査
- 演習モーダル（4択・一問一答・穴埋め）を開くと自動で一時停止
- 対象外: 演習問題の章（19〜22）・用語索引（99）・演習モーダル内。章を跨いだ連続再生はしない
- 制約:
  - **声質・読みの正確さは端末の日本語音声に依存**（読み辞書にない語・文脈で読みが変わる語の誤読は残る）。声の選択 UI はなく、日本語音声を自動選択する
  - **スマホは画面ロック・バックグラウンドで止まる**ことが多い（OS / ブラウザの制約）
  - 一時停止は発話単位（最大約70文字）の頭から読み直す。`speechSynthesis.pause()` が Android Chrome で効かないため、cancel → 再発話で実装している
  - `speechSynthesis` 非対応ブラウザでは ▶ 自体を出さない
- 実装: `templates/script.js` の「読み上げ」ブロック（▶ と操作バーは JS が挿入。HTML テンプレートは無変更）/ `templates/style.css` の `.tts-btn` `.tts-bar` `.tts-reading`

### ランダム問題演習

サイドバー上部「📝 ランダム問題演習」リンクからモーダルを起動。

- ソース: `materials/takken/19-22*.md`（権利関係/宅建業法/法令上の制限/税・その他）
- 出題形式: 4択、全範囲ランダム10問
- 採点: 選択肢クリックで即時正誤判定 → 解説展開 → 「次の問題」で進行 → 最終スコア表示
- 結果画面: スコア + 正答率に加え、**間違えた問題の一覧**（カテゴリ／章／出典・問題文・正解の肢・自分が選んだ肢・解説）を表示。全問正解時は「全問正解 🎉」のみ。一覧は一問一答の結果画面と同じ `.mb-review-*` スタイルを流用する
- 間違えた問題の保持は**セッション内のみ**（`quizWrong` 配列）。モーダルを開き直すとリセットされる。localStorage への蓄積・間違えた問題だけの再出題は未実装
- データ: ビルド時に `quiz.json` を自動生成（`fetch` でロード）
- **これらは本試験の過去問そのものではなく、論点別に作成したオリジナルの4択演習問題**。各問の見出しは出題年度ではなく論点名（例: `### 問題7-1（申込みの場所と事務所等の範囲）`）で管理する
- 解説の描画: `script.js` の `explanationToHtml()` が **軽量 Markdown 変換**を通す（`**太字**` → `<strong>`、`` `code` `` → `<code>`、行頭 `- ` / `1. ` → `・` のリスト行）。解説は教材 Markdown 由来で記法が混じるため。一問一答の解説・間違えた問題一覧でも同じ関数を使う
- 品質チェック: `python scripts/audit_quiz.py` で「正解が複数ある問題」「answer と解説の不一致」「解説の逃げ口上（`ただし本問の正解は肢N` / `一見正しいが` 等）」を検出できる。問題を追加・修正したら必ず実行し、要修正0件・要目視0件を確認すること。**逃げ口上は、解説が自ら判定を濁している＝実質的な複数正解のシグナル**であり、正誤判定の突合だけではすり抜ける欠陥を拾う

#### 回答を学習メモへ追加（PC のみ／4択演習・一問一答 共通）

回答後、解説の下に「📌 テキストに追加」ボタンとメモ入力欄が出る。押すと該当章の学習メモ（右サイドバー・`localStorage`）末尾へ追記される。一問一答（○×）でも同じ UI が出る。

```
--- 演習 2026-08-29 [19-過去問-権利関係-1-1] ---
論点: 意思表示／詐欺・通謀虚偽表示と第三者
解説: 詐欺取消しは善意無過失の第三者に…
メモ: 転得者の善意・無過失を見落とした
```

- 追加先の章は `section` から決定する。**quiz.json と marubatsu.json は section 表記が異なるため、マップは2本ある**（未登録の section は追加UIが出ない）
  - 4択: `script.js` の `SECTION_TO_ID[section]` から末尾の連番を除く（例: `09-宅建業法②業務規制-16` → `09-宅建業法②業務規制`）
  - 一問一答: `script.js` の `MB_SECTION_TO_CHAPTER[section]`（章ID直指定）
  - **どちらかに新しい `section` を追加したら、対応するマップにも登録すること**
一問一答は ○× だけでは後から読めないため、問題文と正解も残す。

```
--- 一問一答 2026-09-20 [01-mb-1] ---
論点: 権利関係／制限行為能力者
問題: 未成年者Aが行った…（正解: ⭕ 正しい）
解説: 民法9条ただし書…
メモ: 日用品の購入は取消不可
```

- 二重追加防止: 追記ヘッダの `[問題ID]` がメモ本文にあれば「✓ 追加済み」表示でボタン無効
- 追加先が表示中の章なら右サイドバーの textarea へ即反映（自動保存の debounce タイマーはクリアする）
- メモ欄は Ctrl+Enter でも追加できる
- 幅 1024px 以下では追加UIを表示しない（右サイドバー自体が非表示になり追加先が見えないため）

### 一問一答（○×）

サイドバー上部「⭕ 一問一答」リンクからモーダルを起動。

- データ: `docs/marubatsu.json`（477問、docs/ 直接管理・ビルド対象外）が**唯一の正**
- ルート直下の `marubatsu.json` は `takken-textbook.html` をローカルで開いたとき用の複製。`script.js` が相対パスで `fetch('marubatsu.json')` するため必要。**手で編集せず** `python scripts/sync_marubatsu.py` で docs から同期する（検証を通してからコピー。失敗時は書き換えず exit 1）
- 出題形式: カテゴリ絞り込み + 問題数選択（10/20/50/100問）でランダム出題、⭕❌の2択即時採点
- **重み付き出題**（既定 ON。設定画面の「苦手・頻出を優先」で切替、OFF は従来の一様ランダム）: 各問題の当選確率を `重要度係数 × 履歴係数` で決める。全問が候補のままで、同一セット内の重複はない（非復元の重み付き抽出）
  - 重要度（`importance` フィールド）: `A` 頻出 ×3 / `B` 標準 ×2 / `C` 低頻度 ×1。未設定は B 扱い。出題中はメタ欄にバッジ表示
  - 履歴: 直近が誤答 ×4 / 未回答 ×2 / 正解1回 ×1 / 連続正解2回以上 ×0.5
  - 正誤履歴は `localStorage` の `takken-mb-stats`（`{ id: { s: 連続正解数, n: 回答数 } }`）、ON/OFF は `takken-mb-weighted` に保存。**端末・オリジン別**（スマホと PC は別履歴）。設定画面に集計（直近誤答／未回答／回答済み）と「履歴リセット」ボタンがある
  - 重要度の付与: `python scripts/apply_mb_importance.py` が section 単位の既定値表（スクリプト内 `_BY_LEVEL`）から **未設定の問題だけ** に書き込む。問題単位で変えたいときは `docs/marubatsu.json` の `importance` を直接書き換える（再実行しても上書きされない）。表に無い section は B
- 回答操作: フッター固定の ⭕❌ ボタン（左 = ⭕ / 右 = ❌）をタップ。PC は `←` = ⭕ / `→` = ❌ のキーでも回答。回答後は「次の問題 ▶」のみ（`←→` でも次へ）
- スワイプ回答（タッチ端末のみ）: 問題エリアを左スワイプ = ⭕ / 右スワイプ = ❌。カードが指に追従し、離すと回答が確定する位置（80px または画面幅の 25% の小さい方）を超えると ⭕/❌ を表示。下の回答ボタンも連動し、引っ張っている側が持ち上がって色付き（確定位置で塗りつぶし）・反対側は薄くなる。手前で離すと元に戻り未回答のまま。回答後は左右どちらのスワイプでも次へ（「次の問題」ボタンが指に追従）。縦方向は従来どおりスクロール。モーダル表示中は左端スワイプでサイドバーを開かない
- スマホ（768px 以下）: モーダルを全画面表示（`100dvh` + セーフエリア対応）。回答ボタンは下部固定で 56px 以上、回答すると解説位置まで自動スクロール
- 結果画面: スコア + 正答率に加え、**間違えた問題の一覧**（カテゴリ／章・問題文・正解・解説）を表示。全問正解時は「全問正解 🎉」のみ
- 回答後は解説の下に「📌 テキストに追加」欄が出る（PC のみ・[回答を学習メモへ追加](#回答を学習メモへ追加pc-のみ4択演習一問一答-共通)）。メモ欄の入力中は `←→` が次の問題へ進まずカーソル移動として働く
- 問題追加: `/takken-marubatsu` スキル（`.claude/skills/takken-marubatsu/`）— 論点提案 → 承認 → 追記 → ルート同期 → push まで対話形式で実行。難問・引っ掛け設計ガイドライン付き

### 穴埋め演習

サイドバー上部「✍️ 穴埋め演習」リンクからモーダルを起動。

- ソース: `materials/takken/00-18*.md`（教材本文全範囲、過去問・索引除外）
- 抽出ルール: 段落内の `**太字**` キーワードを空欄化（長さ 2〜30 文字、純記号除外）
- 出題形式: 全範囲ランダム10問、テキスト入力 → 完全一致判定（NFKC正規化＋空白除去で比較）
- 同一段落内に同じ太字が複数出現 → 全箇所空欄化、1問に集約（1つ入力で全箇所判定）
- 採点: 「採点する」ボタン or Enter → 即時正誤判定 → 不正解時は正解併記 → 「次の問題」で進行 → 最終スコア表示
- データ: ビルド時に `fillin.json` を自動生成（`fetch` でロード）

### テキストブックの再生成

教材ファイル（`materials/takken/`）またはテンプレート（`templates/`）を更新した場合:

```bash
python scripts/build_takken_textbook.py   # HTML + CSS + JS + quiz.json を生成（docs/ にも自動コピー）
git add docs/ && git commit -m "update textbook" && git push
```

> `templates/script.js`・`templates/style.css`、およびスクリプト内の HTML テンプレートは `docs/` の公開版と同期済み（2026-09-20）。フル実行しても一問一答モーダル・分割テキストペインは失われない。
>
> **注意**: `docs/script.js`・`docs/style.css` を直接編集すると次回のフルビルドで上書きされ、機能が退行する（2026-09-20 に実際に発生）。**必ず `templates/` を編集してからビルドすること**。
>
> JSON だけ作り直したい場合は部分ビルドを使う:
>
> ```bash
> python scripts/build_takken_textbook.py --quiz-only     # quiz.json のみ
> python scripts/build_takken_textbook.py --fillin-only   # fillin.json のみ
> ```
>
> テンプレート（`templates/` またはスクリプト内 HTML）を変更したときは、フル実行後に `marubatsu-overlay` / `quiz-textbook-pane` が `docs/index.html` に残っているか確認すること。

### 本文の装飾ルール

教材 Markdown は素のテキストのまま書き、装飾はビルド時に付与する（`build_takken_textbook.py` の `decorate_html()`）。

- **太字**（`**語**`）: 見出しの青と区別するため別色（`templates/style.css` の `--em`）
- **見出し内の `★`**（頻出度）: `<span class="stars">` で包みバッジ表示（`--star`）
- **行頭が `⚠` の箇条書き・段落**: `class="caution"` を付け囲み表示（`--warn-bg` / `--warn-border`）。文中の `⚠` は対象外
- 見出しの強弱: h2（章・青字）> h3（節・薄青帯）> h4（項・左マーカー）> h5（小見出し・淡色）

### 試験ごとの設定（`window.TEXTBOOK_CONFIG`）

`templates/script.js` は、ページが `script.js` より前に定義した `window.TEXTBOOK_CONFIG` を読む。未定義なら宅建の値になる。

| キー | 既定値（宅建） | OSS-DB | 用途 |
|---|---|---|---|
| `storagePrefix` | `takken` | `ossdb` | localStorage のキーの接頭辞（学習メモ・一問一答の履歴・読み上げ速度）。github.io 上で同一オリジンになるため試験ごとに分ける |
| `ttsChapters` | `[0, 18]` | `[0, 98]` | 読み上げ ▶ を出す章番号の範囲 |

- 演習モーダル（4択・一問一答）を持たないページでも動くよう、`closeQuiz` / `closeMarubatsu` / `closeFillin` は要素が無ければ何もしない
- 読み辞書 `TTS_READINGS` は宅建向けだが共用している（OSS-DB の本文で誤爆する語は今のところ無い）

## 使い方

### 法令原文の取得

e-Gov 法令 API **v2** を使用（旧 v1 はデータ更新停止・未施行改正の先取り混入があり使用禁止）。
資格試験は「試験年の4月1日時点で施行されている法令」が出題基準のため、試験対策データは必ず `--asof <試験年>-04-01` を付けて取得する。

```bash
cd projects/study-materials
python scripts/fetch_egov.py --exam takken --asof 2026-04-01   # 宅建士: 2026年度試験基準（15法令）
python scripts/fetch_egov.py                       # 全37法令を取得（現時点の施行版）
python scripts/fetch_egov.py --exam kanteishi       # 不動産鑑定士関連のみ（25法令）
python scripts/fetch_egov.py --exam gyoseishoshi    # 行政書士関連のみ（11法令）
python scripts/fetch_egov.py --law 民法             # 特定法令のみ
python scripts/fetch_egov.py --list                 # 取得対象の一覧
```

各出力ファイルの冒頭に取得日・時点指定（asof）・法令リビジョン・直近改正が記録される。
`data/laws/` は `.gitignore` 済み（ローカル生成物。必要時に再取得する）。

### 法令・教材の鮮度監査

`/study-audit` スキル（`.claude/skills/study-audit/`）で、法令の再取得 → 前年度基準日との差分抽出（= 当年度試験の改正論点）→ `materials/` への反映漏れチェック → 修正までを実行できる。

### NotebookLM への投入

1. `materials/` 配下の学習資料と `data/` 配下の法令原文をコピー
2. NotebookLM で「ソースを追加」→「テキストを貼り付け」
3. 試験ごとに別のノートブックに分けると効果的
